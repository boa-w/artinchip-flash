# 启动卡设计（制作启动卡 / SD 烧卡）

官方 AiBurn 烧录页的**制作启动卡**：枚举 SD 读卡器目标盘 → 写 GPT/MBR 布局 →
格式化 → 写 MMC 镜像，全程需管理员权限（手册 §2.2）。本工具暂只实现
**只读枚举**（CLI `sd-list` / GUI 工具页按钮）；**写卡未实现**，原因与方案如下。

## 1. 现状

| 官方步骤 | 本工具 | 说明 |
|---|---|---|
| SD 目标盘枚举 | 已实现（只读） | `src/sdcard.rs`：Linux 读 `/sys/block`，Windows 先 `Get-Disk` CSV 再 `wmic` 兜底，macOS 解析 `diskutil list`；`sd-list` 支持 `--json` |
| GPT/MBR 布局写入 | 未实现 | 跨平台裸盘写入工作量大（见 §2），先不出写路径 |
| 格式化 / MMC 镜像写卡 | 未实现 | 同上；请用官方 AiBurn 写卡，写前用 `sd-list` 二次核对目标盘 ID |

`sd-list` 输出示例（Windows）：

```
Physical disks (read-only; writing boot cards is not implemented):
  PhysicalDrive0 YMTC PC42Q-512GB-B size=476.9 GiB bus=NVMe
Note: use official AiBurn to write a boot card; double-check the target id first.
```

## 2. 写卡为何暂缓（工作量与风险）

1. **Windows 裸盘路径**：需 `\\.\PhysicalDriveN` + 独占锁卷（`FSCTL_LOCK_VOLUME` /
   `FSCTL_DISMOUNT_VOLUME`）+ 管理员提权，误选系统盘即灾难；当前无 `winapi`
   依赖，不引入新 crate 就写不出安全版本。
2. **GPT/MBR 布局**：官方布局字节（保护性 MBR + GPT 头/分区表 + 预留区）未经抓包
   确认，不得猜测手写；需先对官方写卡做全程抓包 + 写后镜像比对。
3. **跨平台差异**：Linux 需 `O_DIRECT` + `BLKGETSIZE64` + `partprobe` 同步；
   macOS 需 `diskutil unmountDisk` + `IOKit` 独占，三套代码三套测试。
4. **安全门控**：写卡前必须多重确认（目标盘可移动性、容量匹配、系统盘拒绝、
   二次输入盘号），GUI/CLI 共用同一确认流程，当前版本先只给只读探针。

## 3. 写卡实现路线（P2，未排期）

1. 抓包确认官方布局：空 SD 卡经官方写卡后，`dd` 回读前 34 扇区 + 分区表，
   与 `image.target.*` 组件偏移交叉验证。
2. 引入最小平台相关代码（Windows `CreateFileW(\\.\PhysicalDriveN)` 封装、
   Linux `/dev/sdX` 独占打开、macOS `diskutil unmountDisk` 调用），全部只在
   `--i-understand-this-writes-to-disk` 显式确认后可用。
3. CLI 先上 `sd-write --disk <ID> --image <img> --yes-i-am-sure`（默认 dry-run
   只打印将写入的扇区范围），GUI 后上同款二次确认对话框。
4. 保留 `sd-list` 作为写前强制核对步骤：写命令必须先出示 `sd-list` 快照，
   目标盘 ID 不在快照内则拒绝执行。

## 4. 安全警告

- 写卡**不可逆**且选错盘会清空系统盘；本工具在写卡实现前**不提供任何写入口**，
  `sdcard` 模块也无写函数可误调。
- 当前如需制作启动卡：先 `sd-list` 记下目标盘，再用官方 AiBurn 写卡。
